# Audit tools

Scripts that drive the game in headless Chrome to take screenshots and measure frame time. They live outside `src/` and keep their own `package.json`, so `playwright-core` never becomes a dependency of the game.

## Setup

```sh
cd tools/audit
bun install
```

They use the local Google Chrome or the cached Playwright headless shell.

## Servers

| Port | What                                              | Command (from the repo root)                                                                                                                                     |
| ---- | ------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 4173 | The real production build                         | `bun run build && bunx vite preview --port 4173 --strictPort`                                                                                                    |
| 4174 | The harness                                       | `node_modules/.bin/vite tools/audit/harness --port 4174 --strictPort`                                                                                            |
| 4175 | The harness, built to profile                     | `node_modules/.bin/vite build tools/audit/harness --outDir dist-profile && bunx vite preview tools/audit/harness --outDir dist-profile --port 4175 --strictPort` |
| 4179 | The harness, built for production by `perf:check` | Started and stopped by `bun run perf:check`                                                                                                                      |

The harness boots the game's own `init`, `update`, and `view` at a state chosen by query string, such as `?wave=8&start=wave&gun=smg&fill&crowd=30`. It is test tooling only and never ships. `harness/config.ts` decodes the query string once through the `HarnessConfig` Schema, with the defaults below, so an unknown key or a bad value (a typo, `wave=abc`, `gun=uzi`, `seen=Bob`) stops the page with the Schema error on screen instead of quietly showing the default scene. A flag such as `fill` is on when present, with any value or none.

- **The run.** `wave` picks the wave (0, the default, is the home menu), `start=wave` starts it instead of its break, and `mode=endless` starts an endless run. `phase=gameover` or `phase=victory` with `stats` fills the run stats panel, and `phase=paused` pauses the round. `elapsed` starts a wave's clock that many ms in, so the WAVE banner is gone. `prep` sets the break's remaining ms (default 20000), and `break=open` makes it the untimed first break, `breakMs` ms in. `money`, `barricades`, and `turrets` fill the wallet and the trap stock. `device=touch` shows touch wording, and `py` with `px` places the player (`px` alone does nothing, and without `px` he keeps his x). The staged zombies below stand relative to `px`,`py`, which default to 160,90 for them.
- **Guns.** `gun=smg` or `gun=shotgun` gives a spare gun, with `rounds` total rounds, `loaded` in the magazine (the SMG's, default 30), and `tier` its upgrade tier. `pistol` sets the pistol's tier. `aim=x,y` holds the trigger down aimed at that arena point, and `god` keeps the player at full health.
- **The room.** `fill` lays the most decals, `crowd=N` stands N zombies around the room, and `tough` gives them 40 times their health so the room stays full. `gasroom=N` fills the crowd with N Gasbags and walks new ones in at the doors whenever shots and chain bursts pop them. `lineup=wear` stands every kind at every wear stage in rows, `lineup=boss` the boss at each of its five stages, `lineup=sizes` every kind at full health in a row, and `lineup=armor` a Big Lug at each armor stage with the shed pieces launched.
- **New zombies.** `seen` lists the kinds already introduced this session, such as `seen=Shambler,Runner` or `seen=all`. With `start=wave` it also raises the new zombie card for the first kind in the wave that is not on the list, since the card only comes up when a wave starts, and `card` sets the card's age in ms.
- **Power-ups.** `pickups` lays pickups in a row on the floor, such as `pickups=all` or `pickups=Heart,Pierce`, at `pickupY` (default 128) and `pickupAge` ms old (default 2000, so 8300 shows the despawn blink). `boosts` starts boosts, such as `boosts=RapidFire,Damage`, the first with `boostMs` left (default 5000) and each next one 2.2 seconds less, so the last can sit in its expiry blink. `callout=Pierce` puts that power-up's name callout over the player, `calloutAge` ms old (default 400); `callout=Burp` with a small age also shows the burp ring. `bounty` floats three money popups (two kill bounties and a wave bonus) across the middle of the room.
- **The boss.** `boss=arriving|stomp|belch|charge|rush|spit|dazed|fighting` puts the boss in that state: `arriving` rattles `door` (default East) with `arriveMs` left, `stomp` and `belch` start that wind-up with `windMs` left, `charge` braces toward `tx`,`ty` with `windMs` left, `rush` is mid-rush toward `tx`,`ty`, `spit` has a glob in the air toward `tx`,`ty` with `globMs` left, `dazed` is stunned for `windMs`, and `fighting` stalks with `cooldownMs` left. The boss stands at `bx`,`by` with `bosshp` of its health (a share, default 1). `enraged` makes him enraged, and `puddles=x,y;x,y` lays puddles with `puddleMs` left. On wave 8 without `boss`, the boss is planned as the game plans it, so the door preview shows its marker.
- **The other kinds.** `gasbags` stands an idle Gasbag, one shot twice beside the player, and one fusing with `fuseMs` left. `frenzy` stands a frenzied pack and a fading straggler with a HORDE! callout `hordeAge` ms old, and `wipe` adds a pack bonus popup. `chucker=heft|throw|taunt|shield|dazed` stages a Big Leaguer at `cx`,`cy`: hefting a Groaner with `heftMs` left, a Groaner in flight with `flyMs` left, right after a throw, holding a Groaner toward the player as a shield with `shieldMs` left, or a dazed Groaner. `crawler=surfacing|cling` stages an Ankle Biter at `wx`,`wy` with `surfMs` left, or one on the player's ankles.
- **Traps and difficulty.** `planks=West,North` boards those doors with `plankhp`, and `chewers=N` stands Groaners (a Big Lug as the fifth) by the West door. `ask` shows the first-time difficulty card, and `difficulty` and `nightmare` set the setting as in the Model, such as `difficulty=Hard&nightmare=Unlocked`.
- **The home menu.** `best` sets the best endless wave this session, and `bests` gives a session with a best endless wave, a fastest win, and kills. `kills=Shambler:40,Boss:2` sets the kills per kind in the bests, `opened=Shambler,Tank` the Munchopedia entries opened, `newentries=Runner` the NEW ENTRY pop, `homemode=endless` the mode, and `newsseen` marks the newest What's New day seen. `newer` fakes a newer live build (its value, or `next`), and `fit=home` or `fit=full` fakes the full screen check.
- **The look.** `look=Body,Hair,HairColor,Skin,Shirt` sets the character's look, such as `look=Female,Ponytail,Ginger,Tan,Teal` (an empty part keeps the default), `picker` opens the character picker on the screen it starts on, and `looksheet` swaps the game for a sheet of every body, hair style, hair color, and skin tone, plus walk frames, both facings, and the hit flash for four looks.
- **Measuring.** `freeze=N` runs exactly N frames of a fixed 1/60 second with a fixed seed and then holds the picture, so two builds can be compared pixel for pixel. It counts frames only once the surface is measured, and sets `window.__isFrozen` when it holds. `seed` sets the seed without freezing. `instrument` records each frame's `update` and `view` time in `window.__timings`, and `nodev` leaves out the Foldkit DevTools badge.

Measure frame time on a built harness, not the dev server on 4174. The dev server serves unbundled modules with development checks and the Foldkit devtools, and a frame there costs two to three times what it costs in the production build.

## Scripts

Run every heavy script here through the heavy guard from the repo root, never directly: `bun run heavy -- bun tools/audit/perf.ts`, `bun run heavy -- bun tools/audit/profile.ts`, or `TAG=after bun run heavy -- bun tools/audit/shots17.ts`. The guard runs one heavy job at a time across the machine and waits for the load to drop, so frame times are not skewed by a balance run in another worktree. See `tools/heavy/README.md`. The scripts find their files from their own folder, so they work from the root. The commands below are shown by script name. The shared pieces live in `lib.ts`: the browser, the screens (`DESKTOP_1280`, `PHONE_667`, `UPRIGHT_390`, and the rest) and `openPage`, the `TAG`, `BASE`, `ONLY`, and `VIEWPORTS` variables, `harnessUrl`, the pixel compare, and `finish`, which prints the problems and exits with 1.

- `bun run heavy -- bun tools/audit/perf.ts` records `requestAnimationFrame` deltas for the idle, busy, and worst campaign scenarios, two endless ones, `endless15` (endless wave 15) and `endlessCap` (the room held at the alive cap), and `gasbags` (wave 6 with 16 Gasbags kept in the room while the bot pops them). It runs at 1x, 4x, and 6x CPU throttle and writes `perf-<TAG>.json`. `BASE` points it at a server, `ONLY` picks scenarios, and `RATES` picks throttle rates. The scenarios live in `scenarios.ts` and the measuring in `measure.ts`.
- `bun run perf:check` from the repo root is the frame time gate. It runs `perf-check.ts` through the heavy guard. See below.
- `bun run heavy -- bun tools/audit/profile.ts` profiles the worst case at 4x throttle against the profiling build on 4175. It prints the main thread trace by event kind, the top self times, and a CPU profile bucketed into update, scene build, paint, snabbdom, GC, and native time. `SCENARIO`, `RATE`, and `MS` change what it profiles, `FOCUS=fnName` lists the stacks through a function, and `DUMP=path` saves the raw profile.
- `bun shots9.ts` takes frozen, deterministic shots of the title, the preparation phase, two worst-case fights (one mid-shake), endless wave 15, Game Over, Victory, and two phone scenes, as `s9-<TAG>-<scene>.png`. With `COMPARE=<other tag>` it also counts the pixels that differ from that set, which is how a rendering change is checked to look the same.
- `TAG=after COMPARE=before bun shots17.ts` is the camera and depth sort guard: frozen shots of the title, a crowd (still and mid-shake), the stall from the top and the side, power-ups, pickups, the new zombie band and card, the door preview, trap placement, Game Over, every kind at every wear stage, the boss's stages, a room of Gasbags under fire, and the look sheet, on 1280x720 and 667x375, as `s17-<TAG>-<viewport>-<scene>.png`. It waits until the harness reports the frozen frame, so a slow first render cannot change the picture. `COMPARE` counts the differing pixels against another tag and writes `s17-diff-<viewport>-<scene>.png` with the changed pixels in magenta. `COMPARE_ONLY=1` compares without taking new shots, and `ONLY` picks scenes, such as `ONLY=wave,break`, and `BASE` points it at another harness port.
- `bun icons.ts` draws every icon in `public/` from its pixel maps: the 16 pixel `favicon.svg` for browser tabs, and from a bigger 32 cell head on a purple glow the 192 and 512 manifest icons, the 512 maskable icon with the head inside the safe circle, and the 180 Apple touch icon. It also writes a contact sheet of every size on light and dark tab bars and inside the home screen masks to `shots/icons.png`.
- `bun og.ts` draws `public/og-image.png`, the 1200x630 card that link previews show: the title screen's dripping MUNCH MANOR logo (frozen at its first frame), the Groaner head from `icons.ts` on its stepped purple glow, and "TRY NOT TO GET EATEN." in the game's pixel font, over dark floorboards. It loads the logo code from `src/screens.ts` and the head's pixel map from `icons.ts` with a Bun plugin that adds exports at load time, so neither file changes, and paints whole pixel rectangles on a canvas in headless Chrome, so the same art always gives the same file. The card names no wave, feature, or version on purpose: rerun it only when the logo, the font, or the icon art changes. It keeps the head and the logo inside the middle 1000x500, since chat apps crop and shrink the card, and writes `shots/og-600.png` and `shots/og-300.png` to check how it reads small.
- `TAG=after bun shots26.ts` takes the update chip on the title, the iPhone tip, Game Over, Victory, both breaks, pause, and a wave (no chip) on 667x375, 844x390, and 1280x720, as `s26-<TAG>-<viewport>-<scene>.png`, and prints any button or panel the chip overlaps. `PART=e2e bun shots26.ts` is the end to end check on the real build: it builds with `BUILD_ID=e2e-one`, serves `dist/` on 4186, rebuilds with `e2e-two` under the open page, fires `visibilitychange`, taps the chip, and checks the reload runs the new bundle, as `s26-<TAG>-e2e-before`, `-chip`, and `-after`.
- `TAG=after bun shots31.ts` is the gun cluster pass: a wave, a low magazine, a break with traps, a break with traps and a low magazine, and the first break, on 667x375, 844x390, 932x430, and 915x412 phones with touch and on 1280x720 with a keyboard, as `s31-<TAG>-<viewport>-<scene>.png`. It checks that each visible button's center and edges hit that button, that phone buttons are at least 48 px, and that no button covers a doorway, the stall, the player, or another button, and exits with 1 on any problem. `ONLY` picks scenes, such as `ONLY=wave,break`, and `BASE` points it at another harness port.
- `TAG=after bun shots33.ts` is the fixed home layout pass: the home menu fresh (dots on What's New and the Munchopedia), with bests, a NEW ENTRY pop, the update chip, and full screen, in Endless, What's New and an older day, the Munchopedia empty and half found, an unlocked, a locked, and Uncle Chunk's entry, the difficulty picker from the badge, and Game Over with a NEW ENTRY notice, on 667x375 and 844x390 phones with touch and on 1280x720 and 1920x1080 with a keyboard, as `s33-<TAG>-<viewport>-<scene>.png`. On a keyboard it walks the arrow keys from PLAY, shooting each focused button as `s33-<TAG>-<viewport>-focus-<n>.png`, and prints the arrow and Tab orders. It exits with 1 on a phone button under 48 px, two home buttons that overlap, a page or Munchopedia panel that scrolls, or PLAY moving when the mode switches. `ONLY` picks scenes, such as `ONLY=wave,break`, and `BASE` points it at another harness port.
- `TAG=after bun shots34.ts` is the portrait pass: a wave, a low magazine with boosts, a break with the door preview (with the player at each wall, so markers pin to the window's edge), the first break, the shop, the home menu with and without bests, the boss fight, the new zombie card, pause, Game Over, Victory, What's New, the Munchopedia, the character picker, How to play, Settings, and the difficulty picker, on 390x844, 430x932, 360x800, and 375x667 phones held upright and an 844x390 landscape phone, all with touch, as `s34-<TAG>-<viewport>-<scene>.png`. It exits with 1 on a button under 48 px, a button covered at its center or off screen (outside a panel that scrolls), a page that scrolls, or an open dialog past the screen's edge. `ONLY` picks scenes, `VIEWPORTS` picks phones (`p390`, `p430`, `p360`, `p375`, `l844`), and `BASE` points it at another harness port.
- `bun taps.ts` taps every visible button on the home menu (also with full screen, the update chip, and a NEW ENTRY pop), What's New and an older day, the Munchopedia and an entry, the difficulty picker, its other panels, the character picker, the pause screen, the leave question, the gun cluster in a wave and a break with a low magazine, Game Over, and Victory on 667x375 and 844x390 phones, or with `PORTRAIT=1` on 390x844, 430x932, and 360x800 phones held upright (`VIEWPORTS=u390,u360` picks some). It loads the harness with `nodev`, which leaves out the Foldkit DevTools badge, since on a portrait phone the badge sits over buttons at the right edge. It checks that the center and the four edges of each button hit that button with `document.elementFromPoint`, then taps the center and a corner for real and checks that exactly one Message names the tap and that none is a press on the game surface. It exits with 1 on any miss. The harness keeps every Message but the per-frame ones in `window.__messages`. `BASE` points it at another harness port.
- `bun splash.ts` loads the production build (port 4173 by default) at 844x390 with the cache off, unthrottled, on a slow 4G network with 4x CPU, and on a slow 3G network with 6x CPU, and prints when the splash paints, when the game's canvas appears, and when the splash hides and leaves the page, with screenshots as `splash-<TAG>-<profile>-<moment>.png`. `BASE` points it at another server.
- `bun save.ts` loads the production build (port 4173 by default) with no save, picks Normal on the first-run difficulty card, mutes, plays past the wave 1 practice gate, reloads, and checks that the gate stays open and the sound stays muted. It exits with 1 on any miss. `BASE` points it at another server. A save that no longer decodes is covered by `src/store.test.ts`.
- `bun sqlite.ts` checks the save in SQLite on OPFS against the production build (port 4173 by default) or a deployed copy (`BASE`). It seeds an old localStorage save and checks it is imported on the first load, that the database files are in OPFS, that settings changed afterwards come back after a reload while localStorage stays untouched, that a second tab reads and writes through the first, that it takes over the database when the first tab closes, and that two tabs loading at once both read the whole save. It exits with 1 on any miss. Run it through the heavy guard: `BASE=<url> bun run heavy -- bun tools/audit/sqlite.ts`.

## Frame time gate

`bun run perf:check` waits for the heavy guard, then builds the harness for production, serves it on port 4179 (it refuses to start if the port is taken), and plays the `worst` and `endlessCap` scenarios at 1x, 4x, and 6x CPU throttle in headless Chrome, best of two trials each. It compares the results to `frame-baseline.json` and exits with 1 when a gated number regresses past its tolerance.

| Number                   | What it is                                                     | Gate                  |
| ------------------------ | -------------------------------------------------------------- | --------------------- |
| js ms                    | The game's own `update` plus `view` per frame                  | Always. 25% over      |
| main thread ms per frame | All renderer main thread work in the window, painting included | Always. 25% over      |
| fps                      | Frames per second from `requestAnimationFrame`                 | `GATE=all`. 15% under |
| p95 frame ms             | The 95th percentile `requestAnimationFrame` delta              | `GATE=all`. 30% over  |

The two CPU time numbers are the primary gate. Frame deltas swing with how busy the host is, and on a fast machine the game holds the display's refresh rate until it is far over budget, so FPS hides a regression that CPU time shows. The CPU time numbers still slow down on a loaded host, so the check first times a fixed JavaScript workload and scales the CPU limits by how much slower it ran than when the baseline was recorded. Set `GATE=cpu` on a busy machine to report FPS and p95 without failing on them.

- `UPDATE=1 bun run perf:check` records a new baseline. Record it on an idle machine after a deliberate change in cost, and commit `frame-baseline.json`.
- `SCENARIOS`, `RATES`, `SECONDS`, and `TRIALS` change what runs. `JS_TOLERANCE`, `BUSY_TOLERANCE`, `FPS_TOLERANCE`, and `P95_TOLERANCE` take fractions such as `0.25`.
- `BASE=http://localhost:4177/` measures a server you already started instead of building one.

The deterministic half of the guard runs in `bun run test`: `src/perf.scene.test.ts` builds full rooms and counts the canvas shapes and paint operations a frame costs.
