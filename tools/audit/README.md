# Audit tools

Scripts that drive the game in headless Chrome to take screenshots and measure frame time. They live outside `src/` and keep their own `package.json`, so `playwright-core` never becomes a dependency of the game.

## Setup

```sh
cd tools/audit
bun install
```

They use the local Google Chrome or the cached Playwright headless shell.

## Servers

| Port | What                                              | Command (from the repo root)                                                                                                                                     |
| ---- | ------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 4173 | The real production build                         | `bun run build && bunx vite preview --port 4173 --strictPort`                                                                                                    |
| 4174 | The harness                                       | `node_modules/.bin/vite tools/audit/harness --port 4174 --strictPort`                                                                                            |
| 4175 | The harness, built to profile                     | `node_modules/.bin/vite build tools/audit/harness --outDir dist-profile && bunx vite preview tools/audit/harness --outDir dist-profile --port 4175 --strictPort` |
| 4179 | The harness, built for production by `perf:check` | Started and stopped by `bun run perf:check`                                                                                                                      |

The harness boots the game's own `init`, `update`, and `view` at a state chosen by query string, such as `?wave=8&start=wave&gun=smg&fill&crowd=30`. `phase=gameover` or `phase=victory` with `stats` fills the run stats panel, `phase=paused` pauses the round, `device=touch` shows touch wording, and `px` and `py` place the player. `mode=endless` starts an endless run, `tier` sets the spare gun's upgrade tier and `pistol` the pistol's, `rounds` sets the spare gun's total rounds, `best` sets the best endless wave this session, and `tough` gives a `crowd` 40 times its health so the room stays full. `freeze=N` runs exactly N frames of a fixed 1/60 second with a fixed seed and then holds the picture, so two builds can be compared pixel for pixel (it counts frames only once the surface is measured, and sets `window.__isFrozen` when it holds), and `aim=x,y` holds the trigger down aimed at that arena point. `seen` lists the zombie kinds already introduced this session, such as `seen=Shambler,Runner` or `seen=all`. With `start=wave` it also raises the new zombie card for the first kind in the wave that is not on the list, since the card only comes up when a wave starts. `pickups` lays pickups in a row on the floor, such as `pickups=all` or `pickups=Heart,Pierce`, at `pickupY` (default 128) and `pickupAge` ms old (default 2000, so 8300 shows the despawn blink). `boosts` starts boosts, such as `boosts=RapidFire,Damage`, the first with `boostMs` left (default 5000) and each next one 2.2 seconds less, so the last can sit in its expiry blink. `callout=Pierce` puts that power-up's name callout over the player, `calloutAge` ms old (default 400); `callout=Burp` with a small age also shows the burp ring. `bounty` floats three money popups (two kill bounties and a wave bonus) across the middle of the room. `elapsed` starts a wave's clock that many ms in, so the WAVE banner is gone. `lineup=wear` stands every kind at every wear stage in rows, and `lineup=boss` stands the boss at each of its five stages. `boss=arriving|stomp|belch|fighting` puts the boss in that state: `arriving` rattles `door` (default East) with `arriveMs` left, `stomp` and `belch` start that wind-up with `windMs` left, and the boss stands at `bx`,`by` with `bosshp` of its health (a share, default 1). On wave 8 without `boss`, the boss is planned as the game plans it, so the door preview shows its marker. `look=Body,Hair,HairColor,Skin,Shirt` sets the character's look, such as `look=Female,Ponytail,Ginger,Tan,Teal` (an empty part keeps the default), `picker` opens the character picker on the screen it starts on, and `looksheet` swaps the game for a sheet of every body, hair style, hair color, and skin tone, plus walk frames, both facings, and the hit flash for four looks. ## Scripts

The guard runs one heavy job at a time across the machine and waits for the load to drop, so frame times are not skewed by a balance run in another worktree. See `tools/heavy/README.md`. ## Frame time gate

`bun run perf:check` waits for the heavy guard, then builds the harness for production, serves it on port 4179 (it refuses to start if the port is taken), and plays the `worst` and `endlessCap` scenarios at 1x, 4x, and 6x CPU throttle in headless Chrome, best of two trials each. It compares the results to `frame-baseline.json` and exits with 1 when a gated number regresses past its tolerance.

| Number                   | What it is                                                     | Gate                  |
| ------------------------ | -------------------------------------------------------------- | --------------------- |
| js ms                    | The game's own `update` plus `view` per frame                  | Always. 25% over      |
| main thread ms per frame | All renderer main thread work in the window, painting included | Always. 25% over      |
| fps                      | Frames per second from `requestAnimationFrame`                 | `GATE=all`. 15% under |
| p95 frame ms             | The 95th percentile `requestAnimationFrame` delta              | `GATE=all`. 30% over  |

The two CPU time numbers are the primary gate. Frame deltas swing with how busy the host is, and on a fast machine the game holds the display's refresh rate until it is far over budget, so FPS hides a regression that CPU time shows. The CPU time numbers still slow down on a loaded host, so the check first times a fixed JavaScript workload and scales the CPU limits by how much slower it ran than when the baseline was recorded. Set `GATE=cpu` on a busy machine to report FPS and p95 without failing on them.

- `UPDATE=1 bun run perf:check` records a new baseline. Record it on an idle machine after a deliberate change in cost, and commit `frame-baseline.json`.
- `SCENARIOS`, `RATES`, `SECONDS`, and `TRIALS` change what runs. `JS_TOLERANCE`, `BUSY_TOLERANCE`, `FPS_TOLERANCE`, and `P95_TOLERANCE` take fractions such as `0.25`.
- `BASE=http://localhost:4177/` measures a server you already started instead of building one.

The deterministic half of the guard runs in `bun run test`: `src/perf.scene.test.ts` builds full rooms and counts the canvas shapes and paint operations a frame costs.
